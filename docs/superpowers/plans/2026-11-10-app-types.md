# App Types Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the user pick what kind of app they are designing, and derive the whole scheme — neutrals, accents, semantics, text floor, opening harmony and theme — from that type plus the base color.

**Architecture:** `color.js` gains an `APP_TYPES` table (one entry per type, holding the recipe values fixed in the spec) and `buildPalette` gains an `appType` option that applies the recipe while deriving the palette. `app.js` gains an app-type chip list, the `appType` state field, and the rule that picking a type adopts that type's harmony and theme. Nothing about the existing role set, export format, or palette-size control changes.

**Tech Stack:** Static HTML, CSS and vanilla JavaScript (no build step, no dependencies). Tests with `node --test` against the CommonJS export of `color.js`.

**Spec:** `docs/superpowers/specs/2026-11-03-color-theory-design.md` — section "App types" (recipe values, semantics table, invariants). The spec is the source of truth for every number below.

## Global Constraints

- No build step, no dependencies, no framework. Classic scripts, so `file://` still works.
- `General` must reproduce today's behavior byte for byte: `buildPalette(opts)` with no `appType` equals `buildPalette({ ...opts, appType: 'general' })` for every output field.
- `accent-2` stays at least 60° from `accent` for every type, harmony and base hue.
- `text` meets the type's `textRatio` on both `bg` and `surface`, and is never below 4.5:1.
- The accent keeps the base color's hue in every type. Types change saturation and lightness only.
- Uppercase six-digit hex in every export, exactly as today.
- Asset URLs carry a `?v=N` query that is bumped on every deploy so GitHub Pages cannot serve a stale stylesheet against fresh HTML.

## Review Focus

Five inputs the spec implies but no task's tests exercise on their own:

1. **A grey base color** (`#B0B0A0`, saturation ≈ 0.17). The Kids saturation floor must lift it to ≥ 0.68 without inventing a hue the user never chose.
2. **A near-black or near-white base color.** The accent lightness trims must clamp into 0.05–0.95 rather than producing an out-of-range color. Covered by Task 1's "extreme base colors still produce an in-range accent".
3. **A warm accent with the warm neutral types.** Education and Kids tint their neutrals at hue 35 and 45; an accent at hue 30 must still be distinguishable from its own background.
4. **Kids' 7:1 floor on a tinted background.** `deriveText` steps lightness until it reaches the floor; it must reach 7:1 rather than falling back to a ratio below it.
5. **Switching app type after a palette size was set.** The size must survive, and the type's harmony must not reset it.

- [ ] **Step 1: Write the failing test file `tests/app-types.test.js`**

```js
const test = require('node:test');
const assert = require('node:assert');
const C = require('../color.js');

const TYPES = C.APP_TYPES ? C.APP_TYPES.map((t) => t.id) : [];

function hueOf(hex) {
  return C.rgbToHsl(C.hexToRgb(hex)).h;
}

function gap(a, b) {
  const d = Math.abs(a - b) % 360;
  return Math.min(d, 360 - d);
}

test('general is the default and reproduces the current palette', () => {
  const plain = C.buildPalette({ hex: '#6366F1', harmonyId: 'analogous', mode: 'light' });
  const general = C.buildPalette({ hex: '#6366F1', harmonyId: 'analogous', mode: 'light', appType: 'general' });
  assert.deepStrictEqual(general.roles, plain.roles);
  assert.deepStrictEqual(general.extras, plain.extras);
  assert.deepStrictEqual(general.contrast, plain.contrast);
  assert.strictEqual(general.accent, '#6366F1');
});

test('every app type keeps text readable in both themes', () => {
  for (const type of C.APP_TYPES) {
    for (const mode of ['light', 'dark']) {
      for (const hex of ['#6366F1', '#22C55E', '#EF4444', '#0B0D14', '#FAFAFA']) {
        const p = C.buildPalette({ hex, harmonyId: 'analogous', mode, appType: type.id });
        assert.ok(C.contrastRatio(p.text, p.bg) >= 4.5, `${type.id} ${mode} ${hex} text/bg`);
        assert.ok(C.contrastRatio(p.text, p.bg) >= type.textRatio, `${type.id} ${mode} ${hex} floor`);
        assert.ok(C.contrastRatio(p.text, p.surface) >= type.textRatio, `${type.id} ${mode} ${hex} text/surface`);
      }
    }
  }
});

test('kids demands AAA text', () => {
  const kids = C.appTypeById('kids');
  const p = C.buildPalette({ hex: '#6366F1', harmonyId: 'analogous', mode: 'light', appType: 'kids' });
  assert.ok(C.contrastRatio(p.text, p.bg) >= 7);
  assert.ok(kids.textRatio >= 7);
});

test('fintech ignores the base hue for its neutrals', () => {
  const a = C.buildPalette({ hex: '#6366F1', harmonyId: 'analogous', mode: 'light', appType: 'fintech' });
  const b = C.buildPalette({ hex: '#22C55E', harmonyId: 'analogous', mode: 'light', appType: 'fintech' });
  assert.ok(Math.abs(hueOf(a.bg) - 215) < 12);
  assert.ok(Math.abs(hueOf(a.bg) - hueOf(b.bg)) < 12);
});

test('fintech caps the accent saturation', () => {
  const p = C.buildPalette({ hex: '#1DE533', harmonyId: 'analogous', mode: 'light', appType: 'fintech' });
  assert.ok(C.rgbToHsl(C.hexToRgb(p.accent)).s <= 0.55 + 0.01);
});

test('kids lifts a washed out accent without changing its hue', () => {
  const p = C.buildPalette({ hex: '#B0B0A0', harmonyId: 'analogous', mode: 'light', appType: 'kids' });
  const hsl = C.rgbToHsl(C.hexToRgb(p.accent));
  assert.ok(hsl.s >= 0.68 - 0.01);
  assert.ok(Math.abs(gap(hsl.h, hueOf('#B0B0A0'))) < 2);
});

test('every type keeps the accent hue and 60 degrees of separation', () => {
  for (const type of C.APP_TYPES) {
    for (const harmonyId of ['analogous', 'complementary', 'split-complementary', 'triadic', 'tetradic', 'monochromatic']) {
      for (const hex of ['#6366F1', '#1DE533', '#F97316', '#0B0D14']) {
        const p = C.buildPalette({ hex, harmonyId, mode: 'light', appType: type.id });
        if (!p.accent2) continue;
        assert.ok(Math.abs(gap(hueOf(p.accent), hueOf(hex))) < 2, `${type.id} accent hue`);
        if (harmonyId !== 'monochromatic') {
          assert.ok(gap(hueOf(p.accent), hueOf(p.accent2)) >= 60, `${type.id} ${harmonyId} ${hex}`);
        }
      }
    }
  }
});

test('dashboard gives accent-2 a warm hue that stays 60 degrees away', () => {
  const p = C.buildPalette({ hex: '#6366F1', harmonyId: 'split-complementary', mode: 'light', appType: 'dashboard' });
  assert.ok(gap(hueOf(p.accent2), 35) < 20);
  assert.ok(gap(hueOf(p.accent2), hueOf(p.accent)) >= 60);
});

test('extreme base colors still produce an in-range accent', () => {
  for (const type of C.APP_TYPES) {
    for (const hex of ['#0B0D14', '#FAFAFA', '#FFFFFF', '#000000']) {
      const p = C.buildPalette({ hex, harmonyId: 'analogous', mode: 'light', appType: type.id });
      const hsl = C.rgbToHsl(C.hexToRgb(p.accent));
      assert.ok(hsl.l >= 0.05 && hsl.l <= 0.95, `${type.id} ${hex} accent lightness`);
      assert.ok(hsl.s >= 0 && hsl.s <= 1, `${type.id} ${hex} accent saturation`);
    }
  }
});

test('app types carry their own semantics', () => {
  const health = C.buildPalette({ hex: '#6366F1', harmonyId: 'analogous', mode: 'light', appType: 'health' });
  const general = C.buildPalette({ hex: '#6366F1', harmonyId: 'analogous', mode: 'light', appType: 'general' });
  assert.notStrictEqual(health.danger, general.danger);
  assert.notStrictEqual(health.success, general.success);
  assert.ok(C.contrastRatio(health.danger, health.bg) >= 4.5);
});

test('app types declare an opening harmony and theme', () => {
  assert.strictEqual(C.appTypeById('dashboard').mode, 'dark');
  assert.strictEqual(C.appTypeById('developer').mode, 'dark');
  assert.strictEqual(C.appTypeById('kids').mode, 'light');
  assert.strictEqual(C.appTypeById('general').harmonyId, 'analogous');
  assert.strictEqual(C.appTypeById('dashboard').harmonyId, 'split-complementary');
});
```

- [ ] **Step 3: Add the `APP_TYPES` table and `appTypeById` to `color.js`**

Place the table next to `HARMONIES`. Every value is fixed by the spec table — copy them exactly, including `semantics`. Each type object also carries `id` and `label`: `general`/General, `dashboard`/Dashboard, `education`/Education, `kids`/Kids, `fintech`/Fintech, `health`/Health, `developer`/Developer.

`accentSatMin` is `0` for every type except Kids (0.68). `accent2SatMin` is `0` for every type.

```js
  function appTypeById(id) {
    for (var i = 0; i < APP_TYPES.length; i++) {
      if (APP_TYPES[i].id === id) return APP_TYPES[i];
    }
    return APP_TYPES[0];
  }
```

Export `APP_TYPES` and `appTypeById` on the `ColorMath` object.

- [ ] **Step 4: Apply the recipe inside `buildPalette`**

Replace the neutral derivation with:

```js
    var type = appTypeById(opts.appType);
    var idx = light ? 0 : 1;
    var neutralHue = type.neutralHue === 'base' ? h : type.neutralHue;
    var bg = rgbToHex(hslToRgb({
      h: neutralHue, s: type.neutralSat[idx], l: type.neutralBgL[idx]
    }));
    var surface = rgbToHex(hslToRgb({
      h: neutralHue, s: type.neutralSat[idx] - 0.02, l: type.neutralSurfaceL[idx]
    }));
    var text = deriveText(neutralHue, mode, bg, surface, type.textRatio);
```

`deriveText` gains a `minRatio` argument that defaults to `4.5`; its loop condition becomes `contrastRatio(candidate, bg) >= minRatio && contrastRatio(candidate, surface) >= minRatio`, and its final fallback stays `#000000` / `#FFFFFF`.

The accent keeps the typed hex verbatim unless the type actually changes it:

```js
    var accentHsl = rgbToHsl(hexToRgb(accent));
    var accentSat = clamp01(accentHsl.s * type.accentSat);
    accentSat = Math.min(accentSat, type.accentSatMax);
    accentSat = Math.max(accentSat, type.accentSatMin);
    var accentL = clamp01(accentHsl.l + type.accentLight);
    var shaped = rgbToHex(hslToRgb({ h: accentHsl.h, s: accentSat, l: accentL }));
    var accentFinal = (type.accentSat === 1 && type.accentLight === 0 &&
      type.accentSatMax === 1 && type.accentSatMin === 0) ? accent : shaped;
```

`accent-2` uses the same shaping with the type's `accent2*` values, and its hue comes from the harmony partner, except when `type.accent2Hue === 'warm'`:

```js
    var partnerHueValue = rule.partner === null ? null : wrapHue(h + rule.partner);
    var accent2HueValue = partnerHueValue;
    if (type.accent2Hue === 'warm' && partnerHueValue !== null) {
      accent2HueValue = hueGap(35, h) >= 60 ? 35 : partnerHueValue;
    }
```

Monochromatic keeps its lightness-variant `accent-2` untouched by the type.

`accentSoft` mixes `bg` with the final accent by `type.accentSoftMix[idx]` instead of the fixed `0.16` / `0.30`. The semantic colors come from `type.semantics[mode]`.
